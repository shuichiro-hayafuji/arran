# チャット主体の初回相談と購入実績確認

関連: [Issue #16](https://github.com/shuichiro-hayafuji/arran/issues/16)、[チャット主体の支出相談要件](chat-advice-requirements.md)、[対象者と支出相談の体験](target-users.md)、[初版の提供範囲](initial-release-scope.md)

2026年9月27日から10月11日までの対話で、初回相談に必要な情報、チャットからの保存、CSV案内、購入後の確認を決定した。詳細な家計管理を面倒に感じる対象者へ、相談前のフォーム入力を求めないための製品要件である。実装済みの動作を示す文書ではなく、実装と検証は後続Issueで行う。

## 初回相談の始め方

専用の初回登録フローや金額入力フォームを相談の前提にしない。ユーザーが自然な文章で相談を始めた時点で、発言と保存済み情報から必要な情報を組み立てる。不足項目だけを会話で補い、保存情報の一覧表示やプロフィール編集フォームは設けない。

支出相談では、主に次の3項目が助言へ影響する。

- 現在残高
- 当月の自由に使える予算
- 購入予定額

月収、固定費、貯蓄目標、カテゴリ、目標、助言の厳しさも、相談内容に応じて利用する。固定の必須項目や入力期限は設けず、不足や古さが助言へ大きく影響するかをLLMが判断する。

確認が必要な場合は、関連する項目を2〜3件ずつ質問する。追加質問にも回答がなければ、分かっている情報と置いた前提、不確かさを区別して暫定的に答える。情報不足の影響が大きく助言できない場合は、その理由を伝えて相談内容を保持する。

概算値は利用できる。概算専用の入力操作は求めないが、利用者が述べた事実とLLMの推測は区別して保存し、回答でも混同しない。

## LLM、Go、保存処理の分担

ユーザーの発言から金額、対象項目、対象期間を読み取り、金額を計算し、目標や嗜好も含めて助言する処理はLLMが担う。LLMはDBへ直接アクセスしない。プログラムは会話、記憶、嗜好、過去の助言を保存し、相談に関係する情報だけを検索してLLMへ渡す。プログラムは固定の金額計算や最終判定を行わない。

LLMが将来の相談に役立つと判断した内容は、確認操作を挟まずに保存できる。自動保存に固定の信頼度や数値基準は設けない。推測は事実と区別し、情報源と記録時点をたどれるようにする。

保存済み情報と新しい発言が矛盾する場合は、新しい内容を通常利用し、古い内容は変更の経緯として保持する。矛盾や対象期間の不明確さが助言へ大きく影響する場合だけ確認する。利用者はチャットで訂正・削除できる。

収入、固定費、貯蓄目標、現在残高、自由に使える予算、助言の厳しさは、情報源と記録時点を伴う記憶として保存できる。固定の有効期限は設けず、相談時にLLMが古さの影響を判断する。購入予定額は購入確認待ちの情報として保存する。

## 助言の厳しさ

助言の厳しさは1〜10の10段階とし、1を「優しめ」、3を「標準」、10を「超厳しい」とする。未指定時の既定値は5とし、ユーザーが指定した値は継続設定として保存する。

厳しさはLLMによる説明の口調と注意喚起の強さに反映する。同じ事実を都合よく変えたり、相談や支払いを機械的に禁止したりする値としては使わない。

## CSVを使わない場合

CSVは相談の必須条件にしない。CSVがなくても、チャットと保存済み情報から相談できる。ただし、取り込んでいない支出は判断に含まれないことを説明する。

CSV取込は、初回相談の結果を返した後にだけ、より正確に判断するための任意機能として一度案内する。相談前の準備として要求しない。

## 購入後の確認

購入予定は商品、予定額、相談日時とともに「購入確認待ち」として保存する。相談結果から6時間後、同じチャットへ実際に購入したかを確認するメッセージを追加する。

購入済みの場合は実際の支払額を確認する。「予定どおり」などの回答なら予定額を実額として扱う。LLMは実額から現在残高を計算し、購入内容が自由支出なら自由に使える予算にも反映する。プログラムは計算結果と根拠となる履歴を保存する。自由支出か生活上の必要支出かを判断できない場合だけ確認する。

未回答の場合は、次にチャットを利用したときに2回目を確認する。2回目にも答えず別の話を続けた場合は購入済みとみなし、予定額を反映する。チャットを再利用しない間は自動確定せず、6時間ごとの確認も繰り返さない。

確認待ちが複数ある場合は、商品、予定額、相談日時を示してまとめて確認する。回答対象を判別できない場合だけ追加質問する。

自動確定後に「買っていない」「実際は別の金額だった」と申告された場合は、元の履歴を削除せず訂正記録を追加し、残高と自由に使える予算を再計算する。

チャットで確定した支出が後からCSVにも含まれた場合は、日付、金額、内容から同じ支出と判断できれば同一記録として統合する。判断できない場合だけユーザーへ確認し、二重計上しない。

6時間後のチャット確認はP1とする。同時に送るプッシュ通知はP2とし、チャット内の確認処理とは分けて実装する。
