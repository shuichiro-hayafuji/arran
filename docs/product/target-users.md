# Arranの対象者と支出相談の体験

関連: [Issue #13](https://github.com/shuichiro-hayafuji/arran/issues/13)

2026-09-14、開発者本人への対話から整理した製品方針。本人の希望として確認済みだが、他の対象者にも当てはまるか、実際の支出行動が変わるかは未検証。実装済みの動作を示す文書ではない。

## 対象者と解決する問題

お金の管理が苦手で、予算や収支を詳しく把握する習慣がなく、貯金できないことに不安を感じている人を想定する。収支が厳しいと分かっていても、目の前の欲しいものにお金を使いたい気持ちがあり、自分だけでは支出を見送りにくい。

本人への聞き取りでは、赤字を認識しながら任意の支出に迷うこと、赤字の程度を把握していないこと、具体的な赤字額を示されると息苦しくなりそうだという懸念が確認できた。最後の点は実際の画面を試した結果ではなく、本人の予想である。

## 提供する体験と採用理由

収入・おおまかな支出・目標を登録し、お金を払うか迷ったときに相談する。管理を続ける負担を抑えながら、支出を見送る判断を後押しすることを目指す。

- 目標には、今月の収支の黒字化と、期限・金額を決めた貯金を想定する。貯金目標だけでは、まず赤字を止めたい場面を扱えないため。
- 目標に支障がある支出には、短い理由を添えて「今回は見送りましょう」と明確に伝える。本人は、購入できる条件を提示するより、見送りを後押しする助言を望んでいる。
- 最初の回答では詳しい赤字額を並べず、状況と結論を伝える。数字を突きつけられる負担を避けつつ、助言の理由を理解できるようにする。
- 支出先の道徳的な良し悪しではなく、お金の状況と本人の目標に照らして助言する。

例: 今月の支出が収入を上回っている中で、2万5千円の任意の支出を迷って相談する。

> 今月は収入より支出が多くなっているので、今回は見送りましょう。まずは黒字に戻すことを優先しましょう。

この言い方について、本人から求める体験に合うという回答を得た。実際に支出を見送ったという実測結果はない。

## 今回の提供範囲に含めないこと

詳細な家計簿の継続を利用の前提とすること、決済の強制停止、支出先そのものの価値判断は、この体験の対象外とする。投資判断や債務問題の解決、貯金目標の達成保証も今回の提供価値には含めない。これらは今回の議論から整理した範囲であり、個別機能の採否は関連Issueで扱う。

## 未決定・未検証

- 他の対象者にも同じ悩みと利用意向があるか。外部の対象者への聞き取りは実施できていない。
- 相談が実際の見送りや継続利用につながるか。
- 管理が苦手な人でも続けられる入力項目・更新頻度。
- 黒字化と期限付き貯金目標の優先順位、判定方法、情報が不足・古くなった場合の扱い。
- 詳細な金額を希望時に確認できる表示。候補であり、採用済みの仕様ではない。

今回の方針は、Goが金額・最終判断を担いLLMが説明する既存の[サーバー業務ルール](../harness/business/server.md)を変更しない。画面や計算への反映は別途実装・検証が必要。

## 確認方法と今後の扱い

確認方法は開発者本人への対話。対象者像、動機、目標、好む助言表現を確認した。市場調査やアプリでの利用検証は行っていない。

[Issue #11](https://github.com/shuichiro-hayafuji/arran/issues/11)の1週間の価値検証では、既存の実測項目に加えて、助言への納得感・息苦しさ・次も相談したいか、相談せず支出した場面を振り返ることを提案する。#11の完了条件をこの文書で変更したり、実施済みにしたりしない。[Issue #12](https://github.com/shuichiro-hayafuji/arran/issues/12)の機能優先順位も未決定のままとする。

ユーザーは、ここまでの結果を記録して#13を閉じるよう依頼した。これは本人の体験に基づく初期方針として区切る判断であり、元の外部対象者への調査条件を達成したことを意味しない。他の対象者への調査を再開する際は#13を再開するか、後続課題として明示的に管理する。現時点で後続課題は作成していない。
