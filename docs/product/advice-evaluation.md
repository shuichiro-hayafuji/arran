# 支出相談の価値を評価する基準

関連: [Issue #14](https://github.com/shuichiro-hayafuji/arran/issues/14)、[1週間の価値検証 #11](https://github.com/shuichiro-hayafuji/arran/issues/11)

状態: 2026-09-14改訂。「納得して自分で選べたか」を評価の中心に置く方針はユーザー確認済み。相談直後の追加質問、翌日の回答、毎日の記録を前提とする初稿は、対象者に合わないとの指摘を受けて撤回した。測定方法・観測期間・採用／改善／見直し基準まで整理したレビュー版。数値は事前に置く運営上の仮基準であり、ユーザー承認・実装・実測・Issue完了を示さない。

## 確認済みの方針

「助言が判断の助けになり、本人が理由に納得して選べたこと」を価値とする。見送り件数や節約額だけで成功としない。購入・減額・見送り・保留のいずれも、本人が納得して選べたかが重要となる。

[対象者像](target-users.md)に合わせ、利用者がすることは支出を迷ったときに相談することを基本とする。評価のための追加回答や日記を前提にしない。回答を1タップに減らすだけでは、この問題を解決したことにはならない。

## 利用を妨げずに確認できること

次の操作記録を、追加回答なしで測る候補とする。取得の可否はまだコードで確認しておらず、新たな自動計測の実装を決定したものではない。

| 指標 | 測定案 | 分かること・分からないこと |
| --- | --- | --- |
| 初回の助言表示への到達 | 初めて相談を開始した人数を分母、初回相談で助言表示まで到達した人数を分子とする。表示前の離脱・失敗も分母に残す | 相談体験が回答まで届いた割合。納得や「役立った」割合とは異なる |
| 再相談 | 初回利用後7日間を観測できた人を分母、期間内の別日に再相談した人を分子とする。観測期間が不足する人は別記する | 再び使われた事実。再相談がない理由は、迷う機会がなかったのか不満なのか判別できない |
| 相談回数・利用日数 | 同じ期間の開始回数、判断単位の相談件数、利用日数を記録する。通信再試行は利用回数へ加算しない | 使われ方。回数の多さだけでは価値や依存を判定できない |

個人ごとの観測期間は初回相談開始から7日間とする。実施日と計測可否は実施準備で記録する。最初の1人で割合を出す場合も1/1のように実数を併記し、他の対象者に一般化しない。

## 操作記録では判断できないこと

| Issue #14の評価対象 | 負担を増やさない範囲で得られる根拠 | 残る課題 |
| --- | --- | --- |
| 初回に役立った割合 | 通常の相談で本人が自発的に述べた、助言が判断に役立った具体例 | 発言しない人の納得は不明。助言表示率で代用せず、全利用者の価値到達率は未測定とする |
| 翌日の満足・後悔 | 翌日の通常の相談で、前日の判断について本人が自発的に述べた内容 | 日付と対象の判断が分かる場合のみ翌日の事例とする。後日の回想は別扱い。網羅的な翌日評価は未測定 |
| 自分で決める力への悪影響 | 通常の相談や本人からの連絡に現れた、判断を任せきりにする不安、息苦しさ、必要な買い物を諦めた困りごと | 発言がないことは悪影響がない証拠にならない。再相談回数から依存を推定しない |

自発的な発言だけでは偏りがあるため、満足度や後悔率の推定には使わない。実際の購入・見送りも、アプリ内操作や離脱だけで断定しない。会話からの自動感情判定・新たな会話保存・外部LLMへの評価目的の送信は、この案に含めない。

利用後に本人が希望すれば、運営側が短い聞き取りを行う方法は候補になる。ただし、参加・回答を前提にせず、日記や事前準備も求めない。これだけで翌日評価を実測したことにはならない。聞き取り自体の採用も未決定。

## 予定や宿題を作らない質問の案

ユーザーから、計画された作業に見えるものより、iOSの評価ダイアログのようにその場で唐突に聞かれる方が回答しやすいのではないか、という仮説が示された。問題を質問の有無だけで捉えず、予告された作業を覚える・続ける負担を避ける。iOSの例は体験の参考であり、App Store評価の仕組みを製品内の調査へ流用する意味ではない。

以下の方針に沿い、後続の節で頻度・表示条件・文言のレビュー案を定める。

- 通常の利用中、ときどき1問だけ提示する。毎相談後の定型作業や、翌日の回答予定・通知・未回答一覧は作らない。
- 相談文の入力中や助言を読む途中を避け、操作の区切りで表示する。利用者には予告しないが、表示の抽選条件と頻度制限は運営側で定義する。
- その場で選べ、閉じれば終わる。同じ利用中に追質問を重ねず、閉じた直後に再表示しない。回答しなくても相談を続けられる。
- 例: 「この助言、自分で決める助けになりましたか？」に「なった／ならなかった／まだ分からない」。閉じる操作も用意する。これは判断への有用性を聞く例であり、納得と実際の行動の両方を証明する質問ではない。
- 翌日に自然に再訪した人には、対象の相談を短く示して満足または後悔を1問だけ聞く方法も候補。翌日来なかった人へ回答を求めない。後日回答は翌日評価と区別する。
- 悪影響も別の表示機会に扱う。1問に満足・後悔・判断力を詰め込まず、各項目は別々の回答として扱う。

回答数／実際の質問表示数を回答率とし、閉じた数、未回答数、表示対象人数も残す。肯定回答の割合は回答者内の値として示す。翌日再訪者や回答した人に偏るため、全利用者の満足や悪影響のなさへ一般化しない。初回の価値も、初回相談について尋ねた回答とそれ以降の回答を分ける。

この方式の回答率が高いか、利用を邪魔しないかは未検証。少人数では件数と具体例を確認し、比較できる人数が集まる場合は表示機会を揃えて方式を比較する。回答率だけを上げるために表示回数を増やさず、表示後に相談を中断する割合なども確認する。必要な計測や比較条件は実装前に決める。

## 最初に試す表示ルール

以下は初期案として置く運営側の設定。ユーザーへ回答予定は知らせない。回答率の改善が実証された数値ではなく、しつこくならないよう制限した出発点である。

- 助言を表示した後、利用者が自分で相談画面からホームへ戻ったときを表示候補とする。入力・助言表示の途中、エラー対応中、起動直後には出さない。
- 候補ごとの表示確率は50%。1回の利用につき候補の判定は1回だけとし、ホームを行き来して抽選が繰り返されないようにする。
- 実際に表示した後は72時間空け、直近7日間で最大2回。同じ質問を同じ相談について再表示しない。閉じた場合も表示済みとして間隔を空ける。
- 自動表示する質問は常に1問。回答後は閉じ、補足入力へ誘導しない。回答・閉じる操作と相談の継続を切り離す。
- 条件を満たさなければ出さない。未回答を埋めるための通知や再訪依頼をしない。

初回相談開始から7日間を観測し、最終日の翌日回答を扱う場合だけ8日目まで集計する。初回相談についての回答と、後の相談についての回答を区別する。初回に質問を出さなかった人も初回相談者数には残し、質問対象外を不満や失敗へ振り分けない。

## 1問で聞く内容

| 対象 | 質問案と選択肢 | 集計で言えること |
| --- | --- | --- |
| 判断への納得 | 「この助言を参考に、納得して決められましたか？」／決められた・決められなかった・まだ決めていない | 回答者の自己申告による納得。実際の購入・見送りは別の事実 |
| 翌日の満足 | 対象相談を示し「昨日のこの件、自分の判断に満足していますか？」／満足・どちらともいえない・不満・まだ決めていない・覚えていない | 翌日回答者の満足。後悔の有無は別に聞く |
| 翌日の後悔 | 対象相談を示し「昨日のこの件、自分の判断を後悔していますか？」／している・していない・まだ決めていない・覚えていない | 翌日回答者の後悔。満足の逆数として扱わない |
| 判断を任せきりにする悪影響 | 「使い始めてから、アプリがないと支出を決めにくくなりましたか？」／なった・変わらない・決めやすくなった・分からない | 本人が感じる変化。回数から依存を断定しない |

同じ表示機会に項目を順番に聞かない。初回相談の表示機会は納得の1問。その後は、前日の相談があれば満足・後悔から均等に抽選し、なければ納得・悪影響から均等に抽選する。悪影響の質問は別日の利用が2日以上ある人だけを対象にする。これは初期案であり、質問ごとに対象条件と表示件数を記録する。

翌日質問は日本時間の次の暦日に限り、前日の相談が複数なら最新の1件を対象とする。相談の対象が分からない場合は表示しない。満足と後悔は別の回答者・相談になる可能性があるため、対になった評価とは扱わない。低頻度のため、1人・1週間ですべての項目を回収することは期待しない。

## 回答した人と全体の評価を分ける

有効回答は明示的に選ばれ保存された選択肢。閉じる・保存失敗・未回答は含めない。「まだ決めていない」「覚えていない」「分からない」も回答人数には含め、肯定・否定とは別に示す。自動入力や既存画面の初期値を回答として使わない。

同じ人の多用で結果が偏らないよう、判断用の各指標には1人につき期間中最初の有効回答を1件だけ使う。初回価値は初回相談についての回答に限る。残りの回答も捨てず、参考集計と悪影響の確認に使う。

### 初回に役立つ体験へ到達した割合

初回相談開始者数をN、初回相談について質問を表示した人数をE、有効回答人数をR、「納得して決められた」人数をY、明確な否定人数をDとする。

- N/E/R/Y/Dの実数と、表示率E/N、回答率R/E、回答者内の肯定率Y/Rを併記する。分母0は算出不可。
- 全開始者のうち確認できた到達割合はY/N。未表示・未回答・未決定は不明であり、失敗とはしない。
- 全開始者内の到達割合が取り得る範囲は、自己申告を根拠としてY/N〜(N−D)/Nと示す。不明な人が全員未到達の場合と全員到達の場合の幅であり、統計的な信頼区間ではない。
- 例: N=100、E=50、R=20、Y=14、D=4、未決定2なら、回答者の肯定率70%、全開始者で確認できた到達割合14%、不明を含む幅14〜96%。「全利用者の70%に役立った」とは報告しない。

翌日の満足・後悔も、回答者内の選択肢割合、質問の表示・回答人数、翌日に再訪した人数と対象相談者数を併記する。再訪しない人へ結果を補完しない。任意回答なので、人数が増えても回答者の偏りは残る。

製品全体への効果や、市場全体での成功率は今回判定しない。ここでの「採用」は、この対象者に向けた現行の助言方針を、観測できた範囲に基づいて次の開発・検証でも継続する判断を指す。公開範囲の拡大や安全性の証明には使わない。

## 観測期間と必要な材料

- 最初の本人1人・7日間は予備検証。質問の表示・回答・閉じる動作と回収可能性を確認する。価値の総合採用判断には使わない。
- 価値の評価では、対象者像に合う初回利用者を連続28日間受け入れる。各人は初回相談開始から7日間、翌日評価だけ8日目まで観測し、最後の参加者の観測終了で締める。評価版・開始日・締切日は開始前に運営側が記録する。
- 初回の納得・翌日の満足・翌日の後悔・悪影響は、それぞれ30人以上の有効回答を判断の最低条件とする。再相談は7日間観測できた30人以上を必要とする。同じ30人が全問に答える必要はない。
- 質問ごとに回答率R/Eが30%以上であることも採用判断の最低条件とする。低回答率の値だけで方針を採用しない。この条件でも回答者の偏りは解消しない。
- 締切で不足する指標は「材料不足」として終了する。回答が集まるまで密かに期間や質問頻度を変えない。再検証する場合は別の実施記録とし、異なる文言・条件の回答を混ぜない。

30人は少数の1件だけで採用を決めないための運営上の最低数であり、統計的な精度保証ではない。週2回の制限では収集に人数が必要となるが、利用者へ宿題を増やして補わない。

## 採用・改善・見直しの基準

以下の数値を、検証前に承認する初期の判断基準として提案する。業界標準や実証済みの効果基準ではない。初稿で撤回した日々の回答方式は再導入しない。まず納得できる体験が明確な多数を占め、翌日にも過半数が満足し、後悔が少数にとどまることを求める。

| 指標 | 計算と採用の目安 | 基準を外れた場合 |
| --- | --- | --- |
| 初回の納得 | 初回相談についての肯定人数／有効回答人数が70%以上 | 助言の理由・言い方・決定を支える情報を改善 |
| 再相談 | 初回相談開始日の翌日から7日目までの別日に再相談した人数／7日間観測できた初回相談者数が30%以上 | 再利用の価値・入力負担を点検。相談機会がなかった可能性も残し、不満とは断定しない |
| 翌日の満足 | 「満足」人数／有効回答人数が60%以上 | 助言が本人の事情と合っていたかを点検し改善 |
| 翌日の後悔 | 「している」人数／有効回答人数が20%以下、かつ「していない」が60%以上 | 助言の内容と判断後の困りごとを点検し改善。不明が多いだけで低後悔と判定しない |
| 自分で決める力への悪影響 | 「変わらない」または「決めやすくなった」が80%以上、かつ下記の悪影響確認に未解決事項がない | 判断を委ねさせる表現や体験を見直す |

全指標の分母には「まだ決めていない」「覚えていない」「分からない」も含める。不明を除いて肯定率を高く見せない。回答者内の基準であり、非回答者を含む全体の肯定率の基準ではない。

70%・60%は納得と翌日の満足を多数に求めるため、後悔20%は5人に1人を超える後悔を許容して進めないために置く。再相談30%は毎日の利用を要求しないため、悪影響80%は不明が多いまま採用しないための仮基準。結果を見て達成しやすい値へ動かさず、改定理由を記録して次の検証から適用する。

### 総合判断の優先順位

1. **提供方法の見直しを優先する**: 必要な支出の断念や強い苦痛と助言の関連を示す申告が1件でもあれば、採用判断を保留して原因を確認する。生活・健康への支障がある場合は検証利用を中断する。「アプリがないと決めにくくなった」も1件から点検し、診断や依存認定はしない。確認に必要な情報が得られなければ未解決として残す。追加回答を強制しない。
2. **測定の不具合を直す**: 回答義務化、頻度制限違反、既定値の混入、別人の回答混入があれば影響する集計を無効にし、修正後に再検証する。単なる回答後のアプリ終了を、質問への不満と断定しない。
3. **材料不足を区別する**: 各指標の最低人数・回答率を満たさなければ総合判断は材料不足。不足していない指標の結果と、改善すべき具体例は別途記録する。
4. **現行方針を採用する**: 全指標が採用の目安を満たし、悪影響の未解決事項と計測不具合がなければ、現行方針を次の開発・検証でも継続する。効果の一般化はしない。
5. **改善して再検証する**: 材料が揃い、いずれかの指標が目安を外れた場合。失敗した指標と対象の体験を示し、変更後の別観測で再評価する。1件の否定だけで製品全体を停止しない。

例えば、全指標の人数と回答率が足り、納得75%・再相談35%・満足65%・後悔15%／後悔なし70%・悪影響の非悪化回答90%でも、悪影響の申告が未解決なら採用しない。悪影響に未解決事項がなくても満足が50%なら改善。満足の回答人数が10人なら総合判断は材料不足となる。

質問に回答が得られたことと助言の採用は別に判定する。「唐突な質問は回答率が高い」という仮説の証明は、比較群を設けない今回の検証には含めない。

## 現行実装との隔たり

[既存の結果画面](../../mobile/lib/features/consultation/screens/result/result_screen.dart)は、行動・金額・理由・満足・後悔などをまとめて保存する形式。満足・後悔は未入力でも初期値3が保存へ渡るため、その値だけから明示的に回答したかを判別できない。[Repository](../../mobile/lib/features/consultation/repository/consultation_repository.dart)も行動結果と一緒に送信する経路となっている。これはコードの静的確認であり、実機検証ではない。

任意質問の回答を既存の結果記録へそのまま流し込まず、回答の有無・質問の種類・対象相談・表示日時・回答日時・文言の版を区別する必要がある。評価だけの回答から購入・見送りを更新しない。表示頻度の管理、表示・閉じる・回答の計測、所有者の分離も実装上の後続作業とする。既存APIに機能が揃っているとは判断していない。

集計には必要最小限の識別子と選択値を用い、会話全文を計測イベントに含めない。保存期間・削除方法・端末をまたぐ頻度制御は実装前に決める。今回アプリやAPIは変更していない。
