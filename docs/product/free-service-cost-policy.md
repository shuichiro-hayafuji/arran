# 無料提供と利用上限の方針

関連: [Issue #18](https://github.com/shuichiro-hayafuji/arran/issues/18)、[原価実測 Issue #97](https://github.com/shuichiro-hayafuji/arran/issues/97)、[初版の提供範囲](initial-release-scope.md)

2026-09-21の対話で決定した初版の運用方針。無料提供の人数と相談上限、上限到達後の動作、管理者通知、費用の確認方法を定める。DB設定、上限判定、fallback、PagerDuty通知、token利用量の保存、月次集計SQLは実装済み。実際のOpenAI・AWS利用とサポート対応がまだない月について、利用者1人あたりの実測原価を得たとは扱わない。

## 無料提供の範囲

- 無料で利用できる人数は最大30人とする。
- 相談上限の初期値は、利用者1人あたり月30回とする。
- 月間上限はコードの固定値にせず、DBに設定値として保持する。全利用者に適用する初期値と、利用者ごとの上書き値を分け、上書き値がない場合は初期値を使う。
- 初版では管理者がDBを更新して上限を変更する。管理者画面からの変更は後続課題として扱う。
- 現金支出に月間上限は設けない。自動課金も行わない。

「月30回」の1回は、新しい相談を開始した時点で数える。同じ相談内の追加メッセージは回数へ含めない。月の境界は既存の月次処理と同じく日本時間を基準とする。

## 上限到達後の動作

月間上限へ到達した利用者については、以後の相談の追加メッセージ、メモリ抽出、月次レビューを含むOpenAI API呼び出しを止める。新規相談は30回目までOpenAIを利用でき、31回目からGoの決定論的な判定と簡易説明によるfallbackへ切り替え、相談自体は続けられるようにする。上限が変更された場合、または翌月になった場合は外部AIの利用を再開する。

ローカルLLMで説明を生成する方式はP1の[Issue #92](https://github.com/shuichiro-hayafuji/arran/issues/92)で扱う。採用する場合も、金額・カテゴリ・最終verdictはGoを正とし、ローカルLLMへ移さない。

## 管理者への通知

利用者がその月に初めて上限へ到達したとき、管理者へ1件通知する。同じ利用者・同じ月について、相談のたびに重複通知しない。

第一候補はPagerDuty Events APIとする。通知には相談内容、家計情報、氏名、メールアドレスを含めず、環境名、内部利用者ID、対象年月、相談回数、設定上限、発生日時だけを含める。PagerDutyを利用できない場合の代替はメールとし、送信サービス、宛先、再送、通知失敗時の記録方法は実装前に決める。

## 費用と運用負担の確認

OpenAI APIの費用は月20ドル程度を管理上の目安とし、回答には`gpt-5.6-terra`のreasoning effort `medium`を使用する。20ドルは自動停止や自動課金の条件ではない。

2026-09-21に確認した[OpenAI公式のモデル資料](https://developers.openai.com/api/docs/models/gpt-5.6-terra)では、標準料金は100万トークンあたり入力2ドル、キャッシュ入力0.20ドル、出力12ドル。料金は変更され得るため、単価と確認日も月次記録へ残す。

30人が月30回ずつ新しい相談を開始すると、月900相談になる。月20ドルに収めるには、再生成、月次レビュー、メモリ抽出を含めて1相談あたり平均約0.022ドルが目安となる。相談回答は検証不合格時に最大3回OpenAIを呼び出すため、相談回数だけでは費用を保証できない。実際の入出力トークン数、reasoning token、キャッシュ利用、呼出回数を取得して判断する。

毎月末に、次の内容を確認する。

- 登録者数と、その月に実際に相談した人数。
- 利用者ごとの相談回数と、上限へ到達した人数。
- OpenAI APIのモデル、入出力トークン数、呼出回数、費用。
- AWSなどのインフラ費用。
- 問い合わせ件数、対応内容、対応に使った時間。
- 通知件数、通知失敗、障害件数。

問い合わせ対応には、アカウント登録・停止、ログイン支援、相談結果の調査、上限変更、障害時の確認と案内を含む。当面は対応時間を記録し、人件費へは換算しない。AI、インフラ、問い合わせ対応を合算した利用者1人あたりの原価は未実測である。

## 2026-09-21時点の初回確認

ローカルPostgreSQLを読み取り、登録ユーザーは1人、保存済みの相談は0件だった。今回追加した`llm_usage`は作業ブランチのmigrationであり、普段使うDBへはまだ適用していない。このため、過去のOpenAI API利用が0だったとは断定できず、利用者1人あたりのAPI原価も算出できない。

AWS CLIでは認証情報を取得できず、ArranのAWS請求額を確認できなかった。AWSへ未配備であることの証明にもならないため、インフラ費用は未実測として残す。外部利用者からの問い合わせ件数と対応時間についても、月次記録がまだないため未実測である。

したがって、無料提供と上限の方針、および今後の測定方法は決定済みである。利用者1人あたりの原価実測は、実運用データがそろうまでIssue #18を止めないよう、[Issue #97](https://github.com/shuichiro-hayafuji/arran/issues/97)へ切り出した。最初の実利用月の月末に、`monthly_operating_costs`へAWS実費・問い合わせ件数・対応時間を登録し、[月次原価集計SQL](../../server/docs/monthly-cost-report.sql)の結果をIssue #97へ記録する。

## 残る実装と検証

- 無料利用者30人の制御、DBで変更できる全体・利用者別相談上限、日本時間の月次集計、月替わり、同時要求は実装・回帰テスト済み。
- 30回目までは通常モデル、31回目以降はfallback、追加メッセージは件数へ含めない動作をテスト済み。
- 初版の上限変更はDB操作とし、SQL手順を記録済み。管理者画面は後続で検討する。
- PagerDuty Events API通知、月単位の重複防止、失敗記録、次回相談での再試行を実装済み。メール代替はPagerDutyを利用できないと判明した場合の後続課題とする。
- OpenAI APIのtoken利用量をDBへ保存し、モデル単価の確認日・出典と月次集計SQLを追加済み。実OpenAI APIでの保存確認はAPI keyと実リクエストが必要。
- 実際のAWS請求額、問い合わせ件数、対応時間を`monthly_operating_costs`へ登録し、実利用者1人あたりの月次結果を得る作業は、実運用データの発生後に行う。

OpenAI、PagerDuty、AWSを使った確認は、認証情報を持つ実施者が[外部サービス確認手順](../../server/docs/external-service-verification.md)に従って行う。
