# サーバーの業務ルール

- B-S01: チャット相談の金額抽出・計算・解釈・助言はLLMが担い、プログラムは会話・情報の保存と検索を担う。固定のverdictを相談の必須値にしない。金額の構造化項目は整数円とする。既存の取引集計・月次レビューのGo計算は相談の最終判断として使わない。
- B-S02: 欠損と0円を混同しない。固定の必須情報は設けず、不足・古さ・矛盾・期間不明が助言へ大きく影響する場合だけLLMが関連情報を2〜3件ずつ質問する。概算を許可し、本人の事実と推測、情報源・記録時点・対象期間を区別する。未回答なら暫定回答または助言不能として相談を保持する。
- B-S03: チャット相談は構造化出力を検証し、モデル呼出しは初回込み最大3回、全体で22秒に制限する。失敗・不正出力では金融判断を捏造せず、unavailableと相談履歴を保存する。回答の見直しは影響や不確かさを踏まえてLLMが行う。旧Agentの固定判定と決定論的fallbackを新しい相談APIへ接続しない。
- B-S04: 旧Agent経路の相談カテゴリ推定はAgentのfallbackに委ねられ、通常構成ではMockClientのローカル推定を使う。取引分類もローカルで行う。分類の権限を外部モデルへ変更する場合は業務仕様の変更として扱う。
- B-S05: CSVプレビューではDBへ確定保存しない。プレビューは所有者と期限を持ち、現行の有効期間は30分。同一ユーザー内でfingerprintにより重複登録を防ぐ。再起動でプレビューが失われる現行制約を維持する。
- B-S06: 業務データの読取・更新・削除・集計・CSV確定は認証ユーザーに限定する。未割当の旧データを暗黙に別ユーザーへ公開しない。失効セッションは拒否する。
- B-S07: 月次判定は日本時間、保存時刻の外部表現はRFC 3339を基本とする。月境界の変更には回帰テストを伴わせる。
- B-S08: LLMへ渡す取引情報は日付・金額・カテゴリに限定する。CSV原文・加盟店・口座・明細本文を取引コンテキストへ含めない。チャット相談では現在時刻・厳しさ・除去処理済みのメッセージ、直近履歴と関連する過去助言の本文・根拠・前提、関連する記憶のキー・値・期間・出典、現在の購入確認待ち、許可取引DTOと部分データの取得範囲を送る。認証情報と長い番号列を除去するが、自由文を完全な匿名化済みと断定しない。詳細は[チャットの送信境界](../../server/docs/chat-consultation.md)を参照する。
- B-S09: チャット相談ではLLMが選んだ記憶を確認操作・固定の信頼度・有効期限なしで保存する。同じキーの最新情報を使い、旧情報は履歴として残す。「忘れて」の記憶と古い会話を以後のモデル文脈へ再投入しない。旧月次レビューはローカル候補を正とし最大5件、旧結果記録のメモリ抽出は別経路として残る。

確認対象: 予算境界、金額欠損、LLM不正回答と回数上限、CSV再確定、別ユーザーのID指定、月境界、送信DTO。既存テストの所在と実行は [tool](../../tools/INDEX.md) を参照。
