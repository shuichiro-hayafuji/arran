# サーバーの業務ルール

- B-S01: 金額は整数円で扱い、残額・予算超過・最終verdictはGoの決定論的評価を正とする。LLMに金融判断の最終権限を渡さない。
- B-S02: 相談の金額不足は不足として扱い、必要な追加質問を返す。欠損と0円を混同しない。
- B-S03: 相談回答は事実・カテゴリ・verdictと必須項目を検証する。現在の相談生成・修正は初回を含め最大3回。失敗・不正回答では決定論的fallbackを使う。この上限は相談生成の上限であり、全業務の総API回数を意味しない。
- B-S04: 現行の相談カテゴリ推定はAgentのfallbackに委ねられ、通常構成ではMockClientのローカル推定を使う。取引分類もローカルで行う。分類の権限を外部モデルへ変更する場合は業務仕様の変更として扱う。
- B-S05: CSVプレビューではDBへ確定保存しない。プレビューは所有者と期限を持ち、現行の有効期間は30分。同一ユーザー内でfingerprintにより重複登録を防ぐ。再起動でプレビューが失われる現行制約を維持する。
- B-S06: 業務データの読取・更新・削除・集計・CSV確定は認証ユーザーに限定する。未割当の旧データを暗黙に別ユーザーへ公開しない。失効セッションは拒否する。
- B-S07: 月次判定は日本時間、保存時刻の外部表現はRFC 3339を基本とする。月境界の変更には回帰テストを伴わせる。
- B-S08: LLMへ渡す取引情報は日付・金額・カテゴリに限定する。CSV原文・加盟店・口座・明細本文を取引コンテキストへ含めない。利用者自身の自由入力に含まれる情報の扱いは別途検討し、完全な匿名化済みと断定しない。
- B-S09: 月次レビューはローカル候補を正とし最大5件、LLMは説明補助。メモリ候補は根拠・内容があり、信頼度0.7以上の場合に保存する。

確認対象: 予算境界、金額欠損、LLM不正回答と回数上限、CSV再確定、別ユーザーのID指定、月境界、送信DTO。既存テストの所在と実行は [tool](../../tools/INDEX.md) を参照。
