# FB-20261125-11: 未接続 lease guard の再入とコピー

- 対象: 証跡候補のプロセス内解放 guard
- 関連: C-S01、C-S07
- 出典: 2026-11-25 Astra 独立レビュー
- 状態: 対応中

## 指摘と原因

外部 callback を mutex 保持中に呼ぶと、同じ guard に再入した際にデッドロックする。公開値をコピーすると、mutex と解放状態だけが分離し、同じ lease を複数回解放できる。複数 pending と operation のコピーも検査不足だった。

## 対応と検証

確認中または解放済みの状態を共通 state に記録した後で mutex を外し、外部 callback を呼ぶ。エラー・panic は確認未完了のまま残す。値コピーは共通 state を参照し、operation コピーや確認済み operation を拒否する。複数 pending・再入・panic・コピーを race test で検査した。既存 C-S01/C-S07 は十分なため本文追加不要。

`go test -race -count=1 ./internal/evidenceauthority` は PASS。修正前の再現と独立再レビューは未実施。guard は未接続でプロセス外の保証・AWS は未検証。
