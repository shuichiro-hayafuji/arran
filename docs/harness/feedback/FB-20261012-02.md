# FB-20261012-02: 購入予定の商品が金額補足で失われ同額変更が無視された

- 発生日: 2026-10-12
- 最終更新日: 2026-10-12
- 状態: 完了
- 対象領域: server、チャット相談、永続化
- 関連ルールID・正本リンク: B-S02、B-M04、C-S04、[相談の保存・送信境界](../../../server/docs/chat-consultation.md)、[サーバー業務](../../server/business.md)
- 出典: 2026-10-12のIssue #110独立レビューとmain sessionによる採用指示。

## 指摘と根拠

- 期待する結果: 購入予定は商品・予定額・相談時刻を保持し、補足、訂正、商品変更、取り消しを区別する。
- 実際の結果: PendingPurchase.Descriptionへそのターンのraw messageを保存し、金額が同じなら更新を抑止していた。
- 確認済みの事実: 修正前の実行経路とPort・Input定義で未接続を確認し、修正後の振る舞いを回帰テストで再現した。新しいテストを修正前に実行したFAILの記録は取得していない。
- 未確認事項: 実モデルでの抽出・判断品質、実機、本番データは未検証。

## 原因と対応

- 原因: 保存の単体確認に寄り、次の相談のモデル入力までの経路と、自然な会話の変更パターンを結合して確認していなかった。
- 実装の修正: LLMの構造化purchase_change（set/cancel、商品、予定額）を検証して反映。金額のみの補足は既存商品を保持、同じ価格でも商品の変更を保存、null追加回答で維持、明示的cancelで解除。現在の予定も除去処理と忘却cutoffを通してモデルへ渡す。
- 正本の反映: [相談資料](../../../server/docs/chat-consultation.md)、サーバー業務・構成、OpenAPIを更新。既存ルールの責務・送信許可範囲を補足し、別領域へ一律の制約は追加しない。
- 再発防止: 商品の金額補足・金額訂正・同額変更・cancel・null保持・DB summaryとの一致・不正操作と金額・削除後の入力除外を回帰に追加。OpenAI strict schemaの必須項目を確認。
- 適用範囲: #110のチャット入力と確認待ち保存。金融計算はLLMの責務を維持し、購入実績の計上は#22で扱う。

## 再レビューで確認した再発と対策

- 2026-10-12: 再レビューで、forget後に外部入力から除外された商品の金額のみを訂正すると、保存済みの商品名を引き継いで記録時刻を更新し、次の入力に復活させるP2を確認。状態を対応中へ戻した。
- 既存対策の不足: 外部入力のcutoffを確認したが、保存側の商品の引継ぎと新規商品の省略検証が、除去後の入力ではなく元の保存履歴を参照していた。
- 修正: 商品名の省略検証と引継ぎを両方`input.PendingPurchase`へ統一。削除後に利用可能な予定がなければ商品名が必須になり、金額だけのsetを拒否する。最大3回の後はunavailableで会話を保持し、旧商品の記録時刻と表示履歴は更新しない。
- 再発防止: 予定保存→忘却→商品名のない金額setが3回→次の相談を通し、旧商品の記録時刻を更新しないことと、次の外部入力の全項目に旧商品が含まれないことを回帰で固定する。
- 再検証: 関連Goテスト、server・docsハーネスがPASS。新規専用DB `arran_110_forget_fix_test`でpostgresハーネスもPASS。schema、金融計算の責務、購入実績反映の範囲は変更しない。
- 2026-10-12: 商品の省略と引継ぎを同じ除去済み入力へ統一し、保存→忘却→金額setの再試行→次の入力までの回帰で非復活を確認。正規検証後に再完了。
