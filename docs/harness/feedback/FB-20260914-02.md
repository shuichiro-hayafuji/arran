# FB-20260914-02: 価値検証で対象者に日々の管理を求めた

- 発生日・最終更新日: 2026-09-14
- 状態: 完了
- 対象領域: 製品の評価設計
- 関連正本: [対象者像](../../product/target-users.md)、[評価基準](../../product/advice-evaluation.md)
- 出典: 本会話。管理が苦手な対象者は相談直後の追加質問に回答しないとの指摘。

## 指摘と根拠

既存の対象者像は管理を続ける負担を抑える方針だったが、評価案では相談直後・翌日・毎日の回答を求めた。評価者が欲しい指標を先に並べ、利用者の行動負担との整合を確認しなかった。ユーザーは計画や日常の支払い管理も苦手なペルソナであると具体化した。

## 原因と対応

対象者像に管理負担の制約と、評価の際に誰がいつ何をするか確認する原則を追加した。評価基準から追加質問・日記と、それらの回答を前提とする数値基準を撤回した。自動で観測する操作と主観的な価値を区別し、離脱や再相談から納得・後悔・依存を推定しない。任意の1タップに置き換えるだけでは解決としない。

文章による評価設計の修正であり、アプリの振る舞いは変更していない。機械的な語句検査では対象者との整合を保証できないため、専用テストは追加せず内容をレビューした。

## 検証と判定

- PASS: 改訂後の評価手順に、利用者の追加回答や日々の記録を成立条件とする手順がないことを確認。
- PASS: 操作記録を満足・後悔の代替とせず、#14と#11の未測定項目・未完了状態を保持。
- PASS: `python3 tools/harness.py check docs` と製品文書のローカルリンク確認。
- 完了範囲: 指摘された評価案の撤回、対象者像への反映、再発防止の記録。新しい測定案の合意・実装・利用検証は含まない。
- 残る作業: #14で測定方法と判断基準を詰める。文書修正の完了をIssueの完了とは扱わない。

## 追加の対話による補足

2026-09-14、ユーザーは計画された作業に見える負担と、予告なくその場で答える質問の負担を区別した。質問そのものを一律に避けると解釈せず、予定・記憶・継続管理を求めない任意質問を評価案へ追加した。回答率向上は未検証の仮説として対象者像にも記録。日記や回答義務を撤回した既存対応は維持する。
