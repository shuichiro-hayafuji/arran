# FB-20261116-02: Lightsailの種別をまたぐ名前衝突

- 発生日: 2026-11-16
- 最終更新日: 2026-11-16
- 状態: 対応中
- 対象領域: Lightsail本番配備
- 関連ルールID・正本リンク: [C-I03/C-I04/C-I05](../../infra/conventions.md)、[A-I03](../../infra/architecture.md)
- 出典: 2026-11-16の本番再試行。SSM version解決後、StaticIp作成で `Some names already in use` を確認した親作業の報告。

## 指摘と根拠

- 期待する結果: LightsailのInstanceとStaticIpを異なる物理名で作成する。
- 実際の結果: [stack](../../../infra/lib/stacks/spendable-today-stack.ts) が両方へ `arran-production` を指定し、StaticIp作成が拒否された。
- 確認済みの事実: 親作業でstackはROLLBACK_COMPLETE、RETAINのHost/S3/Userは残存、bucket policy/user inline policyはDELETE_COMPLETEを確認。追加回帰も旧実装で名前2件に対し一意名1件となって失敗した。
- 未確認事項: 残存資源を保持したAWS復旧・StaticIp作成の成功。コードの名前修正だけで再deploy可能とは扱わない。

## 原因と対応

- 原因: 種別ごとの個数・保持・公開範囲は検証したが、Lightsailの名前が種別をまたいで衝突する条件を検査していなかった。
- 修正: StaticIpNameだけを `arran-production-ip` に変更する。logical ID・Instance名・S3/User・保持設定は変更しない。
- 回帰: [stackテスト](../../../infra/test/spendable-today-stack.test.ts) がsynth結果のLightsail物理名を種別をまたいで集め、一意性と固定IP名を検査する。
- 正本: C-I04の重要性質テストの不足を補う変更であり、全領域への新ルール追加は不要。
- 適用範囲: 未作成StaticIpの名前だけ。残存資源のimportやrollback復旧は別の確認済み手順で行う。
