# FB-20261125-08: 新規パッケージの依存方針が未登録

- 発生日: 2026-11-25
- 最終更新日: 2026-11-25
- 状態: 対応中
- 対象領域: サーバーの証跡候補とアーキテクチャ検査
- 関連ルールID・正本リンク: [A-S01、A-S05](../../server/architecture.md)
- 出典: 同日の PR #140 最終検証

## 指摘と根拠

- 期待する結果: 新規パッケージの責務と依存先を明示し、正規 server 検証で許可された依存だけが通る。
- 実際の結果・対象コード: 証跡の候補パッケージと PostgreSQL journal の依存を追加したが、[依存境界チェッカー](../../../tools/server_architecture.py) の方針を更新せず `check server` が失敗した。
- 確認済みの事実・再現条件: 新規 internal パッケージには登録済み依存方針が必要である。
- 未確認事項: 修正後の全正規検証と独立レビュー。

## 原因と対応

- 原因・既存の対策で防げなかった理由: Go 単体テストでは依存境界チェッカーを実行しなかった。
- 実装の修正先: 実際の候補間の依存先だけを登録し、正本の責務と未接続の境界を明記した。
- 正本ルールの反映先、または追加不要の理由: [サーバーのアーキテクチャ](../../server/architecture.md) に候補の責務と依存を記載。A-S01 等の既存原則は変更しない。
- 回帰テスト・checker等の再発防止策: 正常な候補依存と、逆向き・application からの不正参照を検査する回帰を追加。
- 適用範囲・他領域への影響: 証跡候補の依存境界に限定。本番での受付や復元切替を有効化しない。
