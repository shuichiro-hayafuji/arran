# FB-20261125-02: 復元照合中の台帳 head と DB の可視性

- 関連ルール: [B-S06](../../server/business.md)、[C-S07](../../server/conventions.md)

## 指摘と根拠

台帳の読み取り実装が checkpoint のポインタを再利用すると、再読時の更新により比較対象の初回 head まで書き換わり、変更の検出を回避し得た。復元 DB の users に RLS が設定されると、利用者のスナップショットが欠損してもデータ不在と誤認する可能性があった。DB 名だけでは異なるクラスタや schema、識別子の再利用を区別できない。

## 原因と対応

初回 head を値として固定し、再読時に同じポインタを更新する偽物の台帳で、追加された退会者を見落として commit・切替しないことを検証する。対象表の RLS と FORCE RLS を拒否し、管理者の RLS bypass の有無に依存しない。候補 fingerprint にクラスタ system identifier、DB OID、schema OID、DB 名を含め、取得エラーや不一致で止める。これらだけでは認証や識別子再利用・同一クラスタの複製の防止を証明できないため、独立した候補証明、停止保持・排他と実際の切替対象との拘束が必要である。

復元の非公開順序制御は偽物の外部依存を使ってのみ検証しており、真の台帳・停止保証・同意照合・切替には接続していない。既存の本人境界と DB 整合性ルールを適用し、全領域の文章ルールは追加しない。

再レビューでは、DB 名だけを変更する旧テストでは system identifier や OID の照合漏れを検出できず、別スキーマにある継承子を親テーブルへの DELETE が対象とし得ると指摘された。クラスタ識別子・DB OID・実際の別スキーマ OID・DB 名をそれぞれ変えた候補を独立に拒否する回帰を追加し、pg_inherits 上で対象表が親または子となる継承を拒否する。別スキーマの継承子を作成する専用 PostgreSQL 回帰を追加した。これらは本番切替の真正性や鮮度を保証するものではない。
