# FB-20261122-03 PostgreSQL移行の登録と旧スキーマの検証

- 発生日・最終更新日：2026-11-22
- 状態：完了
- 対象領域：CSVプレビュー、PostgreSQLの移行と起動
- 関連ルール：[C-S03・C-S07](../../server/conventions.md)、[A-I04](../../infra/architecture.md)
- 出典：[PR #121](https://github.com/shuichiro-hayafuji/arran/pull/121) の統合前レビュー

## 指摘と根拠

PRの作成後、移行ジョブとAPI起動時のスキーマ確認が同じ移行一覧を使うように変わった。PRでは旧一覧にバージョン15を追加しており、現在のmainと競合した。また、追加テストは旧接続・移行APIを使っていた。既存のバージョン14への移行テストは最新のDBからバージョン14の記録だけを削除するため、バージョン15を追加すると移行履歴に欠番ができる。

## 原因と対応

PR作成時の検証は、新しい移行ランナーとの組み合わせを含んでいなかった。[共通の移行一覧](../../../server/internal/infrastructure/persistence/postgres/database.go)に15を登録し、再接続テストには通常起動と同じスキーマ確認を使った。[移行テストの準備](../../../server/internal/infrastructure/persistence/postgres/reconciliation_fixture_test.go)では、対象の直前の版まで実際のSQLを適用する。14と15への移行テストは、意図して起こしたオブジェクト名の重複をSQLSTATEで確認してから、ロールバックと再実行を検証する。旧データと再起動に関する既存のC-S03を適用した。

## 検証と判定

2026-11-22、PRのheadとmainを統合したソースで、次の検証が成功した。

| コマンド | 確認範囲 |
| --- | --- |
| `python3 tools/harness.py check server` | サーバーとAgentの整形、静的解析、テスト |
| `python3 tools/harness.py check postgres` | 専用PostgreSQL 16.15での旧版からの移行、失敗時のロールバック、並行再実行、プレビュー確定結果の再送 |
| `python3 tools/harness.py check postgres-roles` | 移行ロールでの適用と実行ロールでの起動、欠番・将来版の拒否 |
| `python3 tools/harness.py check docs` | ローカル文書の参照先 |

修正前の不整合はコードとマージ結果で確認した。修正前のテスト実行、本番DB、AWSへの配備は検証対象外。
