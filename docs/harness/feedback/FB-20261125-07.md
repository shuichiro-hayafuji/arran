# FB-20261125-07: 相談失敗時の予約返却と退会の競合

- 発生日: 2026-11-25
- 最終更新日: 2026-11-25
- 状態: 対応中
- 対象領域: 相談受付・退会・PostgreSQL
- 関連ルールID・正本リンク: B-S06、C-S07
- 出典: 同日の PR #140 独立レビュー

## 指摘と根拠

- 期待する結果: 未返却の相談予約がある間は退会を受け付けず、返却と状態確定を一体化し、本人が再試行しても他の予約や確定済み結果を変更しない。
- 実際の結果・対象コード: [requests.go](../../../server/internal/infrastructure/persistence/postgres/requests.go) は返却対象の件数を検証せず、失敗後の予約残存・重複失敗を安全に扱えていなかった。
- 確認済みの事実・再現条件: `failed` と `quota_reserved` は同時に存在し得る。返却失敗のまま完了扱いにすると退会可能になり得る。
- 未確認事項: 実運用の全経路の排出と独立証跡による復元照合。

## 原因と対応

- 原因・既存の対策で防げなかった理由: 処理中のみを退会阻害とみなし、レガシー状態と二重 cleanup の状態遷移を十分確認していなかった。
- 実装の修正先: 受付・バッチで未返却を検出し、返却と状態更新の件数を検証。本人の GET で未完了を再実行し、元の error_code を維持する。
- 正本ルールの反映先、または追加不要の理由: 既存 C-S07 の本人境界・冪等性・結果確認に含まれる。
- 回帰テスト・checker等の再発防止策: 分離 DB で競合、別 owner、返却不能、GET 復旧、異なる理由での重複を検証する。
- 適用範囲・他領域への影響: 非同期相談の cleanup に限定。旧 ID なし同期予約、外部副作用および復元照合は別途必要。
