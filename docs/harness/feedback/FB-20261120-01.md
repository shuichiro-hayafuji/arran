# FB-20261120-01: 起動時の完了状態を取り逃して画面遷移が止まる

- 発生日: 2026-11-20
- 最終更新日: 2026-11-20
- 状態: 対応中
- 対象領域: mobile/startup
- 関連ルールID・正本リンク: [B-M03](../../mobile/business.md)、[A-M04](../../mobile/architecture.md)、[C-M02・C-M09](../../mobile/conventions.md)
- 出典: 2026-11-20の実機確認で、ログイン後にインジケータが表示されたまま進まないとの報告（#104）。

## 指摘と根拠

- 期待する結果: ログイン後はプロフィール入力を挟まず相談画面へ進む。
- 実際の結果: [StartupScreen](../../../mobile/lib/features/startup/screens/startup/startup_screen.dart)が初回購読前に決まった遷移先を処理せず、読み込み表示が続く。
- 確認済みの事実: StartupViewModelの生成中に同期的にAsyncDataが設定される。変更通知だけを購読する旧画面では、追加の状態変更がなく遷移しない。
- 未確認事項: 修正版のiPhone上での操作結果。

## 原因と対応

- 原因: 状態変化の購読と初回状態の処理を区別できていなかった。ViewModelの状態確認だけでは、画面が初期完了状態を取り逃す問題を検出できなかった。
- 修正: 画面のinitStateでlistenManualをfireImmediately付きで登録する。遷移はフレーム終了後に行い、画面の破棄と遷移先の変更を確認する。購読の破棄はConsumerStateが管理する。
- 正本ルール: C-M02の副作用・購読寿命、C-M09の画面副作用の検証で十分なため、重複する規則は追加しない。
- 再発防止: [画面の回帰テスト](../../../mobile/test/startup_screen_test.dart)で初期完了、読込後の完了、遷移予約後の画面破棄を検証する。
- 影響範囲: startup画面の購読のみ。認証・API・データ保存・遷移先・見た目は変更しない。
