# FB-20261125-03: 退会受付前の DB 権限検査

- 発生日・最終更新日: 2026-11-25
- 状態: 対応中
- 対象領域: 退会受付・PostgreSQL 権限
- 関連ルール: [C-S07](../../server/conventions.md)
- 出典: Astra 6.2 medium 独立レビュー

## 指摘と対応

`has_table_privilege` に複数権限をカンマ区切りで渡すと、全権限でなく少なくとも1権限を持つ場合に真になる。そのため API に SELECT があってもバッチに必要な DELETE がない状態で受付する可能性があった。権限を一つずつ検査し AND で結合し、隔離 DB の runtime ロールから各権限を一つずつ取り消して受付前検査が拒否することを確認する。

## 検証と残り

- `check postgres-roles`: PASS。各権限を個別に取り消す8ケースを実行。
- この検査は過去のスケジューラ確認と現在の DB 権限を示すものであり、受付後に障害が起きないことを保証しない。
- 全 API 処理の排出と復元後の論理退会状態の照合は未完成であり、受付は強制的に無効としている。
