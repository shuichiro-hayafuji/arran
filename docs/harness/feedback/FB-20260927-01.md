# FB-20260927-01: 支出相談の入力検証と説明制約が全経路で揃っていない

- 発生日: 2026-09-27
- 最終更新日: 2026-09-27
- 状態: 完了
- 対象領域: 支出相談のApplication、Agent、製品方針文書
- 関連ルールID・正本リンク: [B-S01、B-S02、B-S03](../../server/business.md)、[C-S04、C-S06、C-S07](../../server/conventions.md)、[支出相談における登録残高の扱い](../../product/spending-balance-policy.md)
- 出典（レビューURL、または会話の日付と要旨）: 2026-09-27の独立レビュー。継続相談の負数、Agentの返却経路ごとの非保証説明、固定費・貯蓄目標に関する文書と実装の不一致を指摘された。

## 指摘と根拠

- 期待する結果: 継続相談でも引継ぎ後の予定額を含めて負数をAgent実行前に拒否し、すべての相談生成経路で登録残高の限界を1回説明し、製品文書が現行計算を正確に説明する。
- 実際の結果・対象コードへのリンク: `server/internal/application/application.go`の`ContinueConsultation`には負数検証がなく、`server/agent/agent.go`の非保証説明はMock fallbackだけに依存していた。`docs/product/spending-balance-policy.md`には固定費・貯蓄目標が自由予算計算へ反映済みと読める記述があった。
- 確認済みの事実・再現条件: 保存済み相談から負の予定額を引き継げる。primaryまたはrevisionが検証を通過するとMock fallbackを経由しない。現行の月次自由予算残額は、登録された`MonthlyFreeBudget`から当月の自由支出を引いて計算する。
- 未確認事項: 外部LLMの実応答と実機表示は未確認。

2026-09-27の再レビューで、共通の非保証文言をprovider応答の必須項目検証より前に付与していたため、`CurrentSituation`が空の応答でも検証を通過できることを追加で確認した。

同日の最終レビューで、provider応答の検証後に全欄から固定文言を除去していたため、`ReasoningSummary`等が固定文言だけの場合は、検証時には非空でも最終返却時に空になることを追加で確認した。

## 原因と対応

- 原因・既存の対策で防げなかった理由: 新規相談だけを入力境界として確認し、継続相談の値引継ぎ後を検証対象に含めていなかった。説明制約をprovider単位で実装し、orchestratorの全return経路を確認していなかった。文書作成時に自由予算残額の計算実装との照合が不足した。最初の修正では最終出力に固定文言があることだけを重視し、providerの生draftを検証する前に共通処理を適用したため、必須項目の欠損を補ってしまった。次の修正では検証と付与の順序だけを入れ替え、検証後に全欄を正規化したため、検証済みの必須欄を空にできる経路が残った。
- 実装の修正先、または修正不要の根拠: `ContinueConsultation`、Agent orchestratorとprompt、製品方針文書を修正する。
- 正本ルールの反映先、または追加不要の理由: B-S01〜B-S03とC-S04・C-S06・C-S07で入力検証、判定責務、Agent検証、回帰テストを既に定めているため、正本ルール本文は追加しない。製品方針文書の誤記だけを訂正する。
- 回帰テスト・checker等の再発防止策、または不要の理由: 継続相談の明示値・引継ぎ値の負数拒否とAgent未実行、Agentのprimary・revision・fallback全返却経路で固定文言が1回だけ含まれることをテストする。さらに、`CurrentSituation`が空の場合と、`ReasoningSummary`が固定文言だけの場合にprimaryまたはrevisionを受理せずfallbackへ進むことを固定し、正規化、provider必須検証、最終付与の順序を守る。
- 適用範囲・他領域への影響: DB migration、OpenAPI、モバイルDTOは変更しない。非負値同士の残高差は`int64`の範囲内であり、金額型全体の変更は行わない。
