# FB-20261019-01: CSV期限掃除と0行確定の競合

- 発生日: 2026-10-19
- 最終更新日: 2026-10-20
- 状態: 完了
- 対象領域: CSVプレビュー永続化・確定結果
- 関連ルールID・正本リンク: [B-S05](../../server/business.md)、[C-S02/C-S07](../../server/conventions.md)、[永続化契約](../../../server/docs/csv-import-management.md)
- 出典: 2026-10-19のmain実装レビュー。期限掃除と0行確定が競合すると成功receiptが失われる可能性の指摘。

## 指摘と根拠

- 期待する結果: 期限内に受け付けた0行取込も、成功応答の後は同ID再送で同じ結果を取得できる。
- 実際の結果・対象コード: [PostgreSQL保存処理](../../../server/internal/infrastructure/persistence/postgres/import_previews.go)の確定読取に行ロックがなく、別preview保存の期限掃除が対象行を削除できた。終了時UPDATEが0件でも成功扱いとなっていた。
- 確認済みの事実: 通常行のbatch receiptは別テーブルにあるが、0行receiptはpreview行にのみ保存する。掃除は確定側のowner advisory lockを取得していなかった。
- 未確認事項: 修正前コードを実行した再現は未実行。修正後の競合回帰と専用PostgreSQL統合は成功。正規server/postgres検証と独立レビューも完了した。

## 原因と対応

- 原因: 通常のbatch receiptの保証を0行の例外にも当てはめ、確定と期限掃除の別更新経路を並行検証していなかった。
- 修正: PostgreSQLの対象preview読取にFOR UPDATEを追加。両Adapterの終了時UPDATE/DELETEはRowsAffectedが1件でなければrollbackする。
- 正本: [取込管理契約](../../../server/docs/csv-import-management.md)へ対象行ロックと更新件数検証を明記。原子的更新の既存C-S02は十分なため一般ルールを重複追加しない。
- 再発防止: load直後に未来時刻の期限掃除を並行実行し、掃除待機・空receipt保持・期限後再送を検証する。存在しない行への終了処理拒否も両DBで検証する。
- 適用範囲: CSVプレビューの終了と掃除に限定。既存FB-20261012-08/09の実機等の残項目は変更しない。
