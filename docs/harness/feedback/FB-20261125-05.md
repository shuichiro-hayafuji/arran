# FB-20261125-05: 退会と進行中 DB 書込みの停止境界

- 発生日・最終更新日: 2026-11-25
- 状態: 対応中
- 対象領域: 退会受付・日次バッチ・DB 接続寿命
- 関連ルール: [B-S06](../../server/business.md)、[C-S07](../../server/conventions.md)
- 出典: 進行中 HTTP 操作と接続断の独立確認

## 指摘と対応

認証後に始まった書込みはセッション失効後も処理を続行し得る。別接続に advisory lease を保持するだけでは、その接続が落ちてロックが解除された後も実際の書込み接続がコミットし得るため、停止の保証にならない。認証済み本人の行ロックと書込みを同じ PostgreSQL トランザクションで行う未接続の試作部品を追加した。トランザクション接続を強制終了すると書込みは rollback され、成功も返らない。

独立レビューで、接続強制終了自体の失敗でも回帰テストが成功し得ることと、開始通知の待機が無期限になり得ることを指摘された。強制終了の呼出し・成功・callback の正常終了をそれぞれ確認してからコミット失敗を検証し、開始・終了待機に期限と先行エラーの検出を加えた。待機中の callback はテスト終了時にも解放する。試作 callback には Commit を公開しない専用 interface を渡す。

## 検証と残り

隔離 PostgreSQL で別接続からの受付待機、実トランザクション接続の強制終了、親 HTTP 文脈取消後も残る模擬 worker、1 接続 pool の枯渇と復帰を確認した。ただし専用 interface でも callback が別接続や他の所有者へ書き込むこと、外部副作用を起こすことは防げず、同一 package 内での内部アクセスも制限できない。既存 HTTP 全操作・ReminderWorker・外部 AI を網羅していないため、この試作は利用者向け処理に接続しない。実装への適用前に各 repository の所有者制約、トランザクション境界とロック順、切断・結果不明、運用・復元時の独立証跡を改めて検証する。退会受付は強制停止を維持する。
