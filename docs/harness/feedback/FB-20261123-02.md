# FB-20261123-02: 同意境界の実行権限と不確実な応答

- 発生日・最終更新日: 2026-11-23
- 状態: 対応中
- 対象領域: 外部AI送信同意、PostgreSQL、mobile
- 関連ルール: [B-S06](../../server/business.md)、[A-S05](../../server/architecture.md)、[B-M02](../../mobile/business.md)
- 出典: 2026-11-23のAstra 6.2 mediumによる#132の独立レビュー

## 指摘と根拠

ポリシー行への `FOR SHARE` はSELECTだけでなくUPDATE権限を要求するため、本番runtimeの権限制限と両立せず同意と送信を実行できない。mobileは3xx応答を成功として扱う場合があり、撤回結果を誤って表示する。応答喪失・撤回待ち・外部HTTP応答超過・送信後の記録失敗は、成功や送信前拒否と区別する必要がある。

## 原因と対応

専用のロック行への共有・排他ロックにより、policy本文の更新権限を与えず版変更と送信許可を直列化する。実行ロールによる実際の同意・送信・撤回と、policy変更の拒否を同じ専用DBで検証する。mobileはHTTP 200と期待する状態の双方を確認し、通信結果不明時は再取得しても後から状態が変わり得ると伝える。撤回待ちはサーバー側で期限を設ける。送信後の記録失敗、読み取り失敗、応答サイズ超過は送信の有無や終了状況が不明な状態として保持する。完全に受信した401・403・429は拒否応答として扱うが、外部事業者内での処理終了は未検証である。[DB契約](../../../server/docs/database-schema.md)へ保証範囲を記載した。

## 検証と判定

2026-11-23の `python3 tools/harness.py check server`、専用DBでの `check postgres` と `check postgres-roles` はPASS。Mobileの正規ハーネスと最終差分のAstra 6.2 mediumによる独立再レビューはPASS。実際のネットワーク切断、プロセスクラッシュ、外部プロバイダー内の処理終了、本番DBは未確認。

再レビューで、REPEATABLE READの固定snapshotは撤回済みの同意や未完了送信を見落とすこと、HTTP 202や進行中の応答でも完了記録を削除することが指摘された。同意操作のトランザクションはREAD COMMITTEDを明示し、説明版の更新triggerは他の分離レベルを拒否する。2接続で固定snapshotによる古い同意の観測、撤回後の拒否、未完了送信中の版変更拒否を再現した。HTTP 200でも `queued`、`in_progress`、status欠落、JSON不正は結果不明として保持し、202も完了と扱わない。明示的な終端状態の扱いはHTTP応答上の状態に限り、プロバイダー内部の実行終了を独立に保証しない。[DB契約](../../../server/docs/database-schema.md)に前提を追記した。

## 履歴

- 2026-11-23: 指摘に対応し、回帰を追加。その後Mobile検証と独立再レビューを実施。
- 2026-11-23: 固定snapshotと非終端応答に関する再レビューへ対応。専用PostgreSQLの2接続回帰を追加。
- 2026-11-23: さらに、送信のユーザー行ロック待機中に撤回がcommitされる競合と、終端エラー応答のusage記録不足を再レビューで検出。READ COMMITTED指定を外したGo overlayでは撤回後に送信されるFAILを再現し、修正後の同じ回帰はPASS。failed・cancelled・incompleteはusageを各応答につき1回記録してから失敗を返すテストを追加。
- 2026-11-24: 終端応答後の元リクエスト取消でusage保存も取消される問題を再レビューで検出。修正前は取消済み・期限なしのcontextにより回帰がFAIL。利用者IDを保持した独立contextに5秒の期限を設け、取消後も記録を1回試行し、保存失敗はログに残し、マーカー削除失敗はそのまま呼出元へ返す。
