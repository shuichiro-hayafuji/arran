# FB-20261124-02: CSV確定結果が不明な場合の再送と表示

- 発生日・最終更新日: 2026-11-24
- 状態: 対応中
- 対象領域: mobileのCSV確定、API応答と再起動後の復旧
- 関連ルール: [B-M02](../../mobile/business.md)、[C-M03](../../mobile/conventions.md)、[B-S05](../../server/business.md)
- 出典: 2026-11-24のIssue #31継続作業での実装確認

## 指摘と根拠

確定APIの応答が途切れた後、同じ画面で別ファイルを選べるため、前の確定が成功済みでも新規取込を開始できた。共通HTTPクライアントは3xxを正常応答として返し、確定DTOは欠落した件数を0に変換していたため、リダイレクトや不正な200応答を0件成功と誤表示し得た。通信結果不明の後に期限切れや404が返っても、以前の確定が未保存だった証拠にはならない。

## 原因と対応

確定中・結果不明の状態を入力変更と別に管理していなかった。mobileは認証済みAPIで確認した利用者IDと接続先ごとにpreview IDのみを安全なストレージに保存し、認証・保存を確認できない場合は送信を開始しない。結果不明の場合は入力を固定し、同じIDで再送する。結果を受け取っても利用者が終了するまでIDを保持し、同じ利用者の再ログイン後も復元を試みる。確定APIはHTTP 200と必要な結果項目を検証し、リダイレクト・不正応答を成功と扱わない。共通ルールのC-M03とB-S05を適用し、全領域へ別のルールを追加しない。

独立レビューで、期限切れ後の復旧不能、プレビューのセッション切替、空IDの不正receipt、内部に保持される一覧更新エラーを確認した。運用者による未保存確認を明示した再開経路、プレビュー送信時の世代検証、receiptの整合性検証、更新失敗時の成功維持と注意表示を追加する。

追加レビューで、ダイアログ終了アニメーション中のcontroller破棄と狭い画面でのはみ出し、プレビューIDの誤った名称、ファイル選択中のセッション切替を確認した。入力の寿命をダイアログに任せてスクロール可能にし、表示と運用確認手順を修正する。ファイル選択完了時は画面の生存とセッション世代を検証する。

再レビューでは、確定処理中の未commitデータは未保存と誤認し得ることを確認した。再送停止・新規確定防止・受付済み処理の全終了を先に確認し、確認不能ならIDを保持する条件を画面と運用手順へ追加する。実環境での処理終了確認方法は未検証。

## 検証と判定

同一IDの再送、404後の不明維持、入力・resetの抑止、端末保存の失敗、セッション切替、結果表示前の再起動を回帰で確認する。正規 `python3 tools/harness.py check mobile` は整形・解析・99テストがPASSし、`check docs` とOpenAPI YAML構文確認もPASS。Astra 6.2 mediumで独立レビューし、指摘を修正後に再レビューで追加指摘がないことを確認した。実機・本番DB・AWS・旧新版の実際の切替は未確認。端末データの削除や別端末への移行後は旧IDを復元できない。
