# FB-20261012-01: CSVと過去相談の保存経路がLLM入力へ接続されていなかった

- 発生日: 2026-10-12
- 最終更新日: 2026-10-12
- 状態: 完了
- 対象領域: server、チャット相談、永続化
- 関連ルールID・正本リンク: B-S08、A-S02、C-S05、[相談の保存・送信境界](../../../server/docs/chat-consultation.md)、[サーバー業務](../../server/business.md)
- 出典: 2026-10-12のIssue #110独立レビューとmain sessionによる採用指示。

## 指摘と根拠

- 期待する結果: 取込の確定後に許可された明細が次の相談へ反映され、新しい相談から関連する過去の助言と根拠・前提を再利用できる。
- 実際の結果: consultation.Inputはfactsと同じthreadのhistoryだけを持ち、CSV確定と別相談の保存内容を再検索していなかった。
- 確認済みの事実: 修正前の実行経路とPort・Input定義で未接続を確認し、修正後の振る舞いを回帰テストで再現した。新しいテストを修正前に実行したFAILの記録は取得していない。
- 未確認事項: 実モデルでの抽出・判断品質、実機、本番データは未検証。

## 原因と対応

- 原因: 保存の単体確認に寄り、次の相談のモデル入力までの経路と、自然な会話の変更パターンを結合して確認していなかった。
- 実装の修正: Repository Portに同一利用者の取引投影と最大20件の過去相談取得を追加。取引は直近100候補の支出だけを日付・金額・カテゴリで渡し部分データを明示。関連する過去発言・助言を最大6件6000バイトに選別し、削除cutoffを記憶・過去相談・取込時点に適用。SQLite新chat経路では取込所有者も記録する。
- 正本の反映: [相談資料](../../../server/docs/chat-consultation.md)、サーバー業務・構成、OpenAPIを更新。既存ルールの責務・送信許可範囲を補足し、別領域へ一律の制約は追加しない。
- 再発防止: CSV確定前後、許可項目、他利用者、忘却後の旧明細、新規相談からの助言再利用、根拠・前提、取得量の回帰を追加。PostgreSQL所有者検証と、取引DTOに禁止列を足すとFAILするchecker回帰を追加。
- 適用範囲: #110のチャット入力と確認待ち保存。金融計算はLLMの責務を維持し、購入実績の計上は#22で扱う。
