## 指摘と根拠

- 期待する結果: 管理作業を面倒に感じる対象者がフォームへ金額を入力する前提を置かず、自然なチャットから必要情報を抽出し、不足項目だけを質問する。
- 実際の結果・対象コードへのリンク: コミット `825b984` で、現在残高と自由支出予算の入力フォーム、任意項目の展開欄、CSV案内を実装した。
- 確認済みの事実・再現条件: Issue #16の本文は必須項目とCSV案内を決める業務判断であり、入力フォームを採用する決定はなかった。ユーザーとのQ&Aで、専用の初回登録フローを設けない要件を確認した。
- 未確認事項: 後続Issue #110、#22、#111、#112の実装動作、対象者による無支援の利用、実機通知、実CSVとの照合は未確認。

## 原因と対応

- 原因・既存の対策で防げなかった理由: 現行のプロフィール画面とIssue本文の「入力」という表現を利用者の意図とみなし、利用場面と操作方法を確認する前にUIへ具体化した。WORKFLOWはIssue文章の作り方を定めていたが、要件決定前の実装を止める条件が明記されていなかった。
- 実装の修正先、または修正不要の根拠: 暫定のモバイル実装を取り除き、`docs/product/first-consultation-onboarding.md`をQ&Aで確定したチャット主体の要件へ置き換えた。責務分担は先行するIssue #20の確定要件に合わせ、実装を4件の後続Issueへ分けた。
- 正本ルールの反映先、または追加不要の理由: WORKFLOWへ、関連コードを意図の証拠にせず、現在理解・仮提案・未決定事項を分け、確認前に実装しない規則を追加した。
- 回帰テスト・checker等の再発防止策、または不要の理由: 利用者の意図を確認したかは機械判定できないためcheckerは追加しない。要件IssueのレビューでQ&A結果と最終差分を照合し、実装前提を自己解釈で補っていないか確認する。
- 適用範囲・他領域への影響: 業務要件を決めるIssue全般に適用する。確定済み要件に基づく通常の実装まで、毎回Q&Aを必須にはしない。
