# FB-20261116-01: CloudFormation実行roleのbootstrap version参照不足

- 発生日: 2026-11-16
- 最終更新日: 2026-11-16
- 状態: 完了
- 対象領域: CDK bootstrap・CloudFormation実行権限
- 関連ルールID・正本リンク: [A-I08](../../infra/architecture.md)、[C-I04/C-I05](../../infra/conventions.md)
- 出典: 2026-11-16、本番CreateChangeSetでCloudFormation execution roleの `ssm:GetParameters` 不足を確認した配備作業からの報告。

## 指摘と根拠

- 期待する結果: 本番テンプレートの `AWS::SSM::Parameter::Value<String>` が参照する `/cdk-bootstrap/hnb659fds/version` をCloudFormationが解決できる。
- 実際の結果: deploy roleには参照権限があったが、[生成元](../../../infra/lib/bootstrap/template.ts) のexecution roleにはなく、CreateChangeSetが権限不足で失敗した。
- 確認済みの事実: 追加した回帰が旧テンプレートで期待どおり失敗（execution側のSSM statementが空）。公式SARの既存照合記録に `GetParameters` とparameter resource対応がある。
- AWS確認: 親作業で管理者更新後のUPDATE_COMPLETEと限定SSM権限をAPI確認。本番CreateChangeSetが成功しHost/S3/User作成へ進み、SSM参照不足の解消を確認した。後続の名前衝突と復旧は [FB-20261116-02](FB-20261116-02.md) で管理する。

## 原因と対応

- 原因: CDK CLIのversion確認とCloudFormationによるSSM型parameter解決を同じ主体と考え、execution roleの参照を見落とした。静的schema検証と過剰権限ガードだけでは必要権限の不足を検出できなかった。
- 修正: execution roleに正確なversion ARNへの `ssm:GetParameters` だけを追加し、[配布JSON](../../../infra/bootstrap/arran-toolkit.template.json) を再生成。GetParameter、パス列挙、書込みや他parameter参照は追加しない。
- 正本: [bootstrap手順](../../../infra/bootstrap/README.md) に実際の障害と既存スタック更新手順を追記。既存A-I08/C-I04で対応できるため、ルールの重複追加は不要。
- 回帰: [bootstrapテスト](../../../infra/test/bootstrap-template.test.ts) でexecution側のSSM statementが唯一かつ正確なaction/resourceであることを検査。生成同期と公式action照合も維持する。
- 適用範囲: bootstrap権限のみ。本番資源・アプリ・DBの変更なし。
