# FB-20261124-05: 退会削除時の所有者境界と DB スキーマ照合

- 発生日・最終更新日: 2026-11-24
- 状態: 保留
- 対象領域: 退会削除・PostgreSQL・外部送信
- 関連ルール: [C-S07](../../server/conventions.md)、[サーバー構成](../../server/architecture.md)
- 出典: 2026-11-24 Astra 6.2 medium の独立レビューと再レビュー

## 指摘と根拠

- 期待する結果: 本人の削除処理が他人・所有者不明の行を削除せず、送信中や結果不明の処理を完了と扱わない。未知の DB スキーマと曖昧な接続先では処理を拒否する。
- 実際の結果: 初期候補は移行版と対象表名だけを確認しており、未知の所有者表、既知表間に追加された異常な CASCADE 外部キー、`search_path` による別スキーマの表解決を十分に拒否できなかった。外部キーが `NOT VALID` の場合に、定義が一致していても既存の不整合行が CASCADE に巻き込まれ得る点も漏れていた。送信中の管理者通知も削除拒否条件から漏れていた。
- 確認済みの事実: 古い `consultation_messages` には、所有者を含まない単独外部キーと、所有者を含む複合外部キーが併存する。所有者未設定の行が対象相談に紐付く可能性を推測で解決してはならない。
- 未確認事項: 追加した SQL と回帰テストは専用 PostgreSQL で未実行。実 DB 上のカタログ・制約・ロック挙動、復元との整合は未検証。

## 原因と対応

スキーマ移行履歴が一致していても DB の表・外部キーが想定どおりとは限らず、一覧に含まれる表同士の追加制約や表名の解決先まで初期設計で照合していなかった。管理者通知の状態も外部送信中の処理として確認すべきところ、AI 送信と相談処理に着目し漏らした。

非公開の削除部品で対象表をロックし、本人識別と確認、処理中相談・AI 送信・管理者通知、所有者不明メッセージを検査する。関連表の解決先を OID とスキーマで照合し、関連する外部キーの参照元・参照先、順序付き列対、削除時動作と検証済み状態を v17 の契約と照合する。想定外の所有者表や制約も拒否する。

[DB 契約](../../../server/docs/database-schema.md) に部品の制約と未配線・未検証状態を記載した。既存の所有者境界と DB 整合性ルールを適用するため、全領域に共通の文章ルールは追加しない。専用 DB 回帰に未知表、未知外部キー、既知表間の異常 CASCADE、別スキーマへの表解決、未検証の複合外部キーに残った他利用者の不整合行、不整合行を消した後も制約の未検証状態自体が拒否されるケース、送信中通知、途中失敗の rollback、他人・所有者不明データの維持を追加した。

この部品は API や運用コマンドに接続せず、独立台帳・停止と drain の確認・復元後の再公開防止を実装したとは扱わない。外部サービス、端末、ログとバックアップの削除は別範囲である。

再レビューで、既存の不整合行の拒否だけでは外部キー自体の `convalidated` 検査の欠落を検出できないと指摘された。不整合行を除去した後、制約を検証する前にもう一度拒否される回帰を追加し、条件を独立して検査する。
